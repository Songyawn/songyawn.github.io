发表于 2025-04-22 分类于 Python
python eventloop源码解析

入口

从asyncio.run开始看起

events._get_running_loop() 从线程局部变量，即每个线程一个loop_id,保证每个线程只有一个eventloop

那这个loop是怎么初始化的呢，这个asyncio.run就会初始化，先判断如果已经存在eventloop的话是错误。

这个函数中的 lazy_init 先初始化了一个evnetloop，并且关联到这个runner

将传入的协程专程为一个task，那create_task做了什么呢

他创建了一个Task实例，并且在这个task实例中调用了self._loop.call_soon将当前task提交到事件循环中。

  • task如果找到当前的eventloop的？

    • _lazy_init 设置了当前runner._loop可以获取到loop

  • call_soon是做什么的

    • 将self.__step加入到eventloop.ready队列中

  • self.__step做了什么

简单来说就是执行这个task的具体代码，并且在遇见await等阻塞状态时把wake_up加到eventloop.ready队列中，等待下次事件循环执行到他。

  • 那如果是io阻塞操作，它什么时候知道可以wake_up呢 后面看看

回到runner.run，最重要的函数就是self._loop.run_until_complete(task) 这个函数里最重要的是_run_once

执行handle.callback，Handle这个数据结构怎么和Task关联，然后执行到task._step的？

  • call_soon就是生成一个handle（callback=task._step) 所以handle._run()就会执行到_step

  • 所以事件循环就是_ready队列的push/pop/run的过程，当遇见await/io阻塞事件之间ready队列里的下一个任务

  • 如果是io阻塞类task，就将wakeup添加到done_callback中，当io操作完成后会通知这个future任务完成，然后执行callback
